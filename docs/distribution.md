# Distribution — what MINIMAL ships and how

> **Status (M9.6):** boundary-pinning doc. Records the actual
> shipped tree, license matrix, and update-mechanism gap as the
> M9.6 cut finds them. **Not a legal determination.** When the
> posture changes (e.g. signing is added, multi-platform packaging
> lands), update this doc and re-run the regression test that
> guards it — see `tests/release/distribution-inventory.test.ts`.

## 1. Shipped tree

The supported prefix of MINIMAL 1.2.7 ships as a Linux x86_64
release tree rooted at `release/current-linux-x64/`. The tree is
produced by `scripts/release.mts:publishRelease` (called from
`scripts/package.mjs`) and includes:

| Path | What | Source |
| --- | --- | --- |
| `minimal` | Renamed Electron binary | `scripts/release.mts` assemble step |
| `resources/app/` | Stripped `package.json` + `dist/` | `scripts/release.mts` |
| `LICENSE` | MINIMAL ISC notice | repo root, copied |
| `LICENSES.chromium.html` | Bundled Chromium licenses | shipped by Electron |
| `chrome-sandbox` | setuid sandbox helper | shipped by Electron |
| `chrome_*.pak`, `resources.pak`, `snapshot_blob.bin`, `v8_context_snapshot.bin` | Chromium runtime | shipped by Electron |
| `icudtl.dat`, `libffmpeg.so`, `libvk_swiftshader.so`, `libvulkan.so.1`, `vk_swiftshader_icd.json` | ICU + codecs + GPU | shipped by Electron |
| `locales/` | Chromium locale data | shipped by Electron |
| `docs/` | Bundled docs (release notes, runbooks, recovery) | repo `docs/`, copied |
| `ins.md`, `README.md` | Operator-facing pointers | repo root, copied |
| `version` | Electron version (`44.2.0`) | shipped by Electron |
| `release.json` | `formatVersion: 1`, `releaseId`, `version`, `arch`, `createdAt` | `scripts/release.mts` |

The historical record lives under `release/builds/` (two preserved
historical builds). The integrity manifest (`MANIFEST.sha256`) is
written at the `retained` checkpoint of `publishRelease` and
verified by `scripts/verify-release.mts:verifyIntegrityManifest`.

## 2. License matrix

| Component | License | Where to find it |
| --- | --- | --- |
| MINIMAL-authored code | ISC | `LICENSE` (shipped) + repo root |
| Bundled Chromium runtime | BSD-like + multiple per-component | `LICENSES.chromium.html` (shipped) |
| npm dependencies (build + runtime) | per-package | `docs/licenses.md` (rebuilt each release) |
| Provider binaries / SDKs | Per the upstream CLI/SDK terms | `src/runtime/providers/native/index.ts` + provider research (`FUTURE/docs/research/01-codex.md`, `02-claude-code.md`) |
| Recovery / release scripts | ISC (MINIMAL-authored) | repo root |

The npm dependency inventory at `docs/licenses.md` is regenerated
each release cut. The bundled-tree inventory (Electron + Chromium
+ system libraries) ships verbatim inside the release at
`LICENSES.chromium.html` and is regenerated by the Electron
upstream — MINIMAL does not patch those notices.

## 3. Update mechanism

**MINIMAL 1.2.7 ships with NO automatic update path.** The release
artifact is currently unsigned. Quoting the existing script
disclaimers:

- `scripts/package.mjs:8-9`:

  > `if (process.platform !== "linux") throw new Error("Build the Linux application from Linux or WSL.");`

  The release is Linux / WSL only.

- `scripts/verify-release.mts:11-13`:

  > *This script does **not** verify a cryptographic signature; the
  > release artifact is currently unsigned.*

  No detached signature, no `gpg` step, no `cosign` step.

A `Grep` across `src/` for `autoUpdater`, `electron-updater`,
`codesign`, or `gpg` returns no distribution wiring. `package.json`
has no `dist` targets, no deb/rpm/AppImage builder, no Squirrel or
Sparkle hook. The supported install path is therefore: download the
release tarball, extract, run the `minimal` binary. The recovery +
rollback story is `docs/update-rollback.md`.

Research doc 12 line 59 makes the platform-update asymmetry
explicit: *"Electron's built-in autoUpdater supports Windows/macOS
and directs Linux applications toward distribution package managers.
Its macOS update path requires signing. Therefore, one update
mechanism cannot be assumed across MINIMAL's proposed environments."*
MINIMAL has not chosen an update path for any platform.

## 4. Freshness rule

Every release bump re-validates this doc. The regression test at
`tests/release/distribution-inventory.test.ts` asserts:

1. This doc exists and contains the four required §-headings.
2. `scripts/verify-release.mts` still carries the "unsigned" disclaimer.
3. `scripts/package.mjs` still aborts on non-Linux platforms.

A release cut that wants to flip either assumption (e.g. add a
signer, ship a deb) MUST update both this doc and the cited script
in the same commit. The test failure is the signal.

## 5. Counsel-gate reminder

Quoting research doc 12 lines 70-78 verbatim — these are documented
differences and review questions, not legal conclusions:

> Before selecting reused code or bundled components, produce a
> versioned artifact inventory for counsel: MINIMAL-authored code,
> competitor-derived code, provider binaries/SDKs, plugins, and
> dependencies. Identify each license and the exact
> distribution/hosting model; a top-level repository license does
> not settle every bundled component. ELv2-derived hosted
> functionality needs a specific assessment before that business
> model is chosen.
>
> For provider confirmation, supply the actual local or hosted
> architecture, authentication path, account owner, credential
> custody, and billing flow. Resolve the distinct CLI/SDK conditions
> recorded in Codex research and Claude commercial gate. Do not infer
> MINIMAL's rights from another vendor's subscription integration.
> Recheck when introducing hosted/shared machines or changing account
> handling.
>
> Before public branding, have counsel check the MINIMAL name and
> proposed provider-name/logo usage; confirm provider branding
> conditions where necessary. Before distribution, review the actual
> installer and notices. These gates attach to concrete packaging
> choices, not to an assumption that a paid wrapper is automatically
> allowed or forbidden.

M9.6 does NOT assert permission to ship, host, or brand MINIMAL in
any particular way. This section is a pointer to research doc 12 and
to counsel; it is not legal advice.

## 6. Out of scope (M9.6)

The M9.6 cut deliberately does NOT add any of the following:

- Cryptographic signing (gpg, cosign, sigstore).
- Notarisation (Apple notarytool, Windows HCK).
- Distribution package builders (deb, rpm, AppImage, tar.gz with signing).
- Auto-update wiring (electron-updater, Squirrel, Sparkle).
- Provider-name or logo usage (deferred to counsel per research doc 12 line 78).
- Hosted-execution surfaces (research doc 12 lines 55-56, 76).

These are explicitly future work, scoped out of M9.6.
