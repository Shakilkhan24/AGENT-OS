# MINIMAL — current-build review, 2026-09-12

Follow-up: the six reproduced/source-identified defect groups are repaired in the [1.2.1 baseline](build-snapshot-v1.2.1.md). This document retains the original review as historical evidence.

MINIMAL is a useful, extendable desktop MVP. Its stack and service boundaries are appropriate for this product, but the current build should not yet be treated as a hardened v1.2 release. Targeted checks reproduced persistence and terminal-delivery defects. These warrant repairs before a large feature expansion; they do not warrant starting over.

Reviewed `main` at `0cdde5e`, comparing the six commits after `4855b3e` with the earlier foundation. That diff contains 48 files, approximately 4,167 additions and 120 deletions, including substantial test additions. The existing uncommitted edit in `tests/core.test.ts` was present during testing and was preserved. This review changes documentation only.

**Replicated defects and priority fixes**

1. **P1 — Shutdown can finish before an active write, and journal writes can finish out of order.** In [`debouncer.ts`](../src/main/debouncer.ts), `run()` clears `pending` before awaiting the writer. `flush()` and `close()` inspect only `pending`, so they cannot see active work. A controlled writer confirmed both returned before completion. Another probe blocked revision 1, allowed revision 2 to finish, then released revision 1: completion order was `[2, 1]`. This permits an older event-journal snapshot to replace a newer one. A failed writer rejects `schedule()` but `flush()` resolves; [`event-bus.ts`](../src/main/event-bus.ts) also discards the scheduled promise without a rejection handler. Track active work, serialize writes, and propagate persistence failures through shutdown.

2. **P1 — Recovery can overwrite the state it claims to preserve.** [`store.ts`](../src/main/store.ts) returns writable empty defaults after invalid JSON/schema errors, without quarantining the original. The next ordinary save replaces `state.json`. A malformed-state fixture followed by one preset edit left only the replacement `state.json`; the original bytes were lost. Preserve a recovery copy before allowing writes, including when an unsupported future schema is encountered.

3. **P1 — A rejected save still changes live state.** [`workspace-state.ts`](../src/main/workspace-state.ts) publishes the new in-memory value before validation/persistence succeeds. Injecting a disk-write failure made `update()` reject while memory contained the edited value and disk still contained the old value. This can expose rejected changes to snapshots and later saves. Publish committed state after successful validation/persistence, or explicitly model pending state with rollback.

4. **P1 — Actual multiline right-click paste is broken.** [`Terminal.tsx`](../src/renderer/Terminal.tsx) manually adds bracketed-paste markers before calling `term.paste()`, which already adds markers when the application enables that mode. In an isolated Electron window using clean Bash, pasting two commands separated by an actual newline produced `bash: $'\E[200~printf': command not found`. The first output file was empty and the second was absent. Let xterm handle its paste protocol and assert actual command results in regression coverage.

5. **P1 — Sustained Unicode output can freeze the attachment.** The renderer acknowledges `data.length` (UTF-16 code units), while [`pty-attachment.ts`](../src/main/pty-attachment.ts) adds UTF-8 bytes to its outstanding budget. A paced helper emitting 1,024,000 bytes of Greek text stalled at 524,288 received bytes with the current acknowledgement units. The same transport received all 1,024,000 bytes when acknowledged in UTF-8 bytes. This is a transport reproduction using the renderer's counting logic, rather than an Electron throughput benchmark. Use consistent byte accounting throughout.

6. **P2 — Input delivery failures lost their acknowledgement path.** Source inspection shows [`index.ts`](../src/main/index.ts) calls the asynchronous `attachment.input()` without awaiting or catching its promise. Its synchronous `try/catch` cannot handle queue/pipe rejection. The renderer now sends every paste chunk without waiting for delivery, and still budgets input in code units. This risks dropped input and unhandled rejections under pressure. Restore bounded, observable delivery with cancellation between chunks. This failure mode was identified in code; a full queue-overflow desktop reproduction was not performed.

The full 87-scenario desktop suite and packaging/package smoke were not run during this review. No claim is made that the complete release checklist passes.

The benchmark does not establish the original targets for warm tab switching, real launch-to-first-prompt, 128 real terminals or main-to-renderer event delivery. Its event timings measure enqueueing, and it has no performance failure threshold. Normal `WorkspaceState.update()` also waits for `Store.save()` inside its mutex, despite comments claiming save resolves on acceptance; consecutive mutations generally pay the 50 ms debounce delay individually.

Test names should be treated cautiously. The existing “multi-line” paste fixture contains literal backslash-n text rather than actual line breaks. Several terminal assertions can match echoed input without proving execution. Existing shutdown tests do not cover the active-writer race above; SIGKILL cannot execute `will-quit`. Settings and hooks tests mostly exercise records/API results, not management screens or hook execution.

**Guidance for the next implementation round**

Keep the present stack and useful service boundaries. First fix persistence serialization/recovery/commit behavior and terminal paste/byte accounting, with deterministic regressions that assert durable state and actual shell results. Then stabilize the failing tests and correct the completion claims. Measure real terminal and renderer performance before accepting further latency tradeoffs.

Additional ordinary feature tabs can use focused React components and the existing backend facade. Multiple simultaneous terminal panes or observers need an attachment registry and an explicit resize/input ownership policy first. A typed, versioned IPC contract and renderer event delivery should precede an automation layer. Avoid growing `App.tsx` to hold each new feature. No database, marketplace or orchestration rewrite is needed to complete these repairs.
