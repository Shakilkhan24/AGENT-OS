## Invariants

Preserve §13 of `build-snapshot-v1.1.md`: GUI lifetime does not own work; reconnect never launches; cancellation of a batch stops between items without killing completed launches; recovery never silently replays arbitrary commands; file containment is not process isolation; schema changes migrate and preserve a prior copy.

## Git discipline

No remote has been requested; commits stay local unless a remote/push is explicitly authorized. The full suite is required before any push.

## Decisions and verification

Baseline verified: typecheck/build, 13 backend cases, 3 desktop scenarios, sandboxed packaged test (12 switches in 2,612 ms; all processes survive GUI closure). File changes will begin with shared contracts and backend services, then move into the renderer after those boundaries are tested.

### Change 1 — operation primitives

Added bounded cancellable FIFO mutex, atomic JSON writes, structured error envelopes, daily NDJSON logs with payload redaction, and Zod-validated profile settings. Production console calls now use structured logging. Validation: `npm run check` passed (18 backend/module cases and production build). Existing §13 process/replay invariants remain covered by the unchanged core suite.

### Change 2 — durable events

Discriminated shared event contracts and a bounded, atomically persisted event bus now validate payloads and sequence order, report replay gaps, and deliver only after persistence. Typecheck and dedicated replay/restart/corrupt-journal tests pass.

### Change 3 — explicit state migration

Added validated v2 records for launch intent history, environment profiles, disabled-by-default hook definitions, session metadata and terminal lifecycle fields. Migration preserves original v1 bytes in a synced, content-addressed backup and refuses unsupported versions. Environment resolution reserves engine-owned keys. Validation: `npm run check` passed (23 cases); the additional synced-backup adjustment passed its migration test.

### Change 4 — engine boundary

Separated the shared EngineAdapter contract, tmux implementation and disposable PTY transport. Length-prefixed tmux metadata preserves tabs, newlines and UTF-8 paths; PTY queue accounting now uses bytes. Socket naming remains compatible with existing profiles. Validation: `npm run check` passed (24 cases), including real terminal input, exit preservation and reconnect invariants.

### Change 5 — tmux lifecycle safety

Profile runtime/configuration ownership checks, explicit environment propagation and clean-shell mode now back advertised engine capabilities. Existing servers receive idempotent configuration updates. Disposable `wait-for` clients receive pane exit hooks on tmux 3.4; polling will remain the recovery path. Stop policies use bounded `/proc` enumeration and recheck UID/start ticks before signalling descendants. Accounting remains best effort (escaped descendants, permission failures and PID races cannot be eliminated). Validation: typecheck, profile/protocol/watcher/adapter/process-accounting tests and all 13 original real backend scenarios pass; a resistant process tree escalates through interrupt/TERM/KILL while its neighbour stays alive.

### Change 6 — independent application services

Replaced the global work queue with short state commits, a launch coordinator, coalesced reconciliation and a stop coordinator. Launch intent has 24-hour idempotency keys, a bounded queue, per-item progress and cancellation between items. Engine creation/deletion shares only the affected terminal's lock. Reopening never replays unfinished launch intent. Events persist status/failure transitions in batches; polling and exit hooks now run in the main process. Stop tombstones retain their chosen policy and permit explicit retry. Validation: `npm run check` passed 34 cases, including blocked-launch responsiveness and concurrent deletion; the final policy-persistence adjustment passed typecheck and focused stop/migration tests.

### Change 7 — file safety and recovery

File operations now have typed request/results, correlated versioned Python envelopes, a bounded cancellable mutex and deadlines that replace a stuck disposable worker. Saves require the opening hash and recheck the path immediately before atomic replacement; the UI shows the external version and requires a fresh reviewed hash. No atomic content-CAS exists against non-cooperating external writers, so the final check/rename window remains a documented limit. Text drafts mirror to private bounded files and restore after restart; serialized cleanup prevents late saves from resurrecting discarded drafts. Listings use descriptor cursors and virtual rows, binary classification reads headers first, recursive deletion has entry/depth bounds, and WSL fallback interruption has deterministic process-death tests. FilePanel is now 325 lines with a separate editor. Validation: `npm run check` passed 41 cases (including four Python helper cases); final typecheck/build and all four real desktop scenarios passed. The new desktop scenario covers conflict review, draft restoration and virtual rows. Full IPC versioning, optional watching and the remaining workspace UI are subsequent stages.

### Change 8 — performance and durability

Debounced writes (state.json and the event journal) collapse a burst of mutations into one `fsync` inside a trailing-edge window; the latest args always win. `flush()` returns when the in-flight write lands; `close()` drains and disarms. A reusable `Debouncer<T>` underpins both writers and is unit-tested for coalescing, latest-wins, flush, close, and failure propagation. State views are frozen and zero-copy so the reconciler and snapshot builder no longer deep-clone on every read. Concurrent `snapshot()` calls share a single in-flight engine `inspect()` — a 25-call burst resolves in 1.85 ms. The renderer's xterm output is coalesced per animation frame and the `input` IPC handler became fire-and-forget; the workspace poll dropped from 2 s to 4 s. A new `runWithWatchdog` helper caps shutdown at 5 s so a wedged fsync cannot hang `will-quit`. Malformed `state.json` is now non-fatal at startup: the file stays on disk byte-for-byte, the in-memory state falls back to the empty default, and the renderer surfaces the reason through a `startup-recovered` IPC after `did-finish-load`. The launch-error UX no longer fires a confusing global toast; per-tab failure surfaces are enough, and the renderer auto-selects the first failed terminal. Validation: 58 backend cases (including new `tests/durability.test.ts` and `tests/shutdown.test.ts`) and 87 desktop scenarios (including a new `tests/shutdown-flush.spec.ts` covering force-kill durability). Hot-path numbers live in `scripts/bench.mts` (`npm run bench`).
